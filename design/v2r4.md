### 指示書: `GIP_LABEL` 環境変数によるIssue起票時のラベル動的指定機能の実装

あなたは優秀なPythonエンジニアです。
現在のコードベースに対して、Issue起票時に付与するラベルを環境変数でカスタマイズできる機能を追加してください。

#### 1. 仕様要件

* **環境変数:** `GIP_LABEL` を参照し、その値をIssueのラベルとして使用する。
* **デフォルトの挙動:** 環境変数 `GIP_LABEL` が未指定、あるいは空文字の場合は、ラベルを一切付与せずに（ラベルなしで）Issueを起票する。コード内に元々ハードコードされていた `"gip"` という固定値は廃止する。
* **プラットフォーム依存の挙動:** 指定されたラベルがリポジトリに存在しない場合のエラーハンドリングは追加不要です（GiteaではID取得時に無視されてラベルなしで起票され、GitHubでは権限によって新規作成されるか無視されるなど、各プラットフォームのAPI仕様にそのまま委ねます）。

#### 2. 修正指示

以下の2箇所を修正してください。

**修正箇所 A: ヘルプメッセージ（`argparse`）の更新**
`main()` 関数内の `argparse.ArgumentParser` の `epilog` を更新し、`GIP_LABEL` の説明（未指定時はラベルなしとなる旨）を追記してください。

```python
    parser = argparse.ArgumentParser(
        prog="gip",
        description="git intent picker",
        formatter_class=argparse.RawDescriptionHelpFormatter,
        epilog="""
環境変数:
  GIP_REMOTE_TYPE     github または gitea (デフォルト: github)
  GIP_REMOTE_TOKEN    APIアクセス用のトークン
  GIP_REMOTE_URL      APIのベースURL (giteaの場合は必須)
  GIP_LABEL           Issueに付与するラベル名 (未指定時はラベルなし)
"""
    )

```

**修正箇所 B: `main()` 関数内での環境変数取得と起票処理への適用**
`main()` 関数の中で Issue を起票するループ処理の前に環境変数 `GIP_LABEL` を取得し、値の有無に応じたリストを生成してください。そして、ハードコードされている固定の `["gip"]` の代わりにそのリストを使用するように変更してください。

【変更後の期待されるコード例】

```python
    # 環境変数を取得（未指定時は None または 空文字 になる）
    target_label = os.environ.get("GIP_LABEL")
    # 値が設定されていればリストにし、なければ空のリストにする
    labels_to_apply = [target_label] if target_label else []
    
    # ... 中略 ...
    
    for i, data in enumerate(extracted_blocks_flat, 1):
        # ...
        print(f"🚀 [{i}/{total_blocks}] Issueを起票中: {issue_title}")
        
        # 固定文字列 ["gip"] ではなく、組み立てた labels_to_apply を渡す
        issue_url = publisher.create_issue(issue_title, issue_body, labels_to_apply)
        created_issue_urls.append(issue_url)

```

Gitea側、GitHub側ともに、`create_issue` メソッド自体のシグネチャ（引数に文字列のリストを受け取る仕様）は変更する必要はありません。`main()` 側の呼び出し元のみを修正してください。
